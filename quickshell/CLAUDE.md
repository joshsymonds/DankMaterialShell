# DMS quickshell — shell + shaders

Personal fork of DankMaterialShell on branch `josh/local`. Upstream is `AvengeMedia/DankMaterialShell`. Refresh: `git fetch upstream && git rebase upstream/master && git push -f`.

## Shader iteration

For tuning chrome-family shaders (`chrome_hexrain`, `chrome_aurora`, etc. in `Shaders/frag/`), use the live-reload harness — **don't** rebuild via the nix flake input bump loop:

```bash
cd ../dev/shader-preview && ./preview.sh
```

The harness opens a Quickshell window with a side panel of sliders (numeric uniforms) and hex inputs (color uniforms), auto-built from `uniforms.json`. Drag sliders to mutate live; click **Save** to persist back to `uniforms.json`. Editing the `.frag` directly recompiles to `.qsb` on save (`qsb` from `qt6.qtshadertools`). Both paths reload within a frame.

When values are settled, run `dev/shader-preview/to-nix.sh` — it prints the corresponding `home-manager/dms/default.nix barConfigs[0]` snippet for paste-back into the consumer's nix-config.

### What lives where

| File                                             | Role                                                                                          |
|--------------------------------------------------|-----------------------------------------------------------------------------------------------|
| `Shaders/frag/<name>.frag`                       | GLSL source. Edit this.                                                                       |
| `Shaders/qsb/<name>.frag.qsb`                    | Compiled bytecode. Regenerated by `qsb` on every `.frag` save. **Commit alongside the .frag.**|
| `Widgets/ChromeShader.qml`                       | Production wrapper. Property declarations here drive `ShaderEffect` uniforms in the bar.      |
| `Modules/DankBar/BarCanvas.qml`                  | Consumer — wires `barConfig.shader*` keys to `ChromeShader`.                                  |
| `../dev/shader-preview/ShaderPreview.qml`        | Standalone harness — independent from production wrapper.                                     |
| `../dev/shader-preview/uniforms.json`            | Live-tweaked uniform state. Schema: `{ shader: {std140-name: value}, harness: {...} }`.       |

### Adding a knob

A new shader uniform requires three coordinated edits inside `quickshell/`:

1. `Shaders/frag/<name>.frag` — add to the `std140` uniform block, use in the body.
2. `Widgets/ChromeShader.qml` — add matching `property real <name>: <safe-default>` on `root` AND on the inner `ShaderEffect`. Safe default = the value that reproduces today's behaviour for production callers.

…plus one harness edit outside `quickshell/`:

3. `../dev/shader-preview/ShaderPreview.qml` — add the property on the `ShaderEffect`; add a `hints` entry for slider min/max/step.
4. `../dev/shader-preview/uniforms.json` — add a default value.

Then **restart `preview.sh`** — QML doesn't hot-reload, only the `.frag` and `uniforms.json` do.

### Switching to a different shader family

`wp_*` shaders use a different uniform set. To preview one:

- Change `FRAG` / `QSB` constants in `dev/shader-preview/preview.sh`.
- Change `qsbPath` in `ShaderPreview.qml`.
- Replace `uniforms.json` `shader` block with the new shader's uniform names.
- Declare any new uniforms as properties on the harness `ShaderEffect`.

### Two-repo commit dance

The `.frag`, `.qsb`, harness, and `ChromeShader.qml` live here in DMS. Color values live in nix-config (`home-manager/dms/default.nix`). When shipping a shader change:

1. Tune in the harness, save `uniforms.json`.
2. Commit DMS: `.frag` + `.qsb` + `uniforms.json` (+ `ChromeShader.qml` if new uniforms) — they ship together.
3. Push `josh/local`.
4. In nix-config: bump the `dms` flake input, paste the `to-nix.sh` output into `home-manager/dms/default.nix`, run `update`.

The .qsb is binary and committed — DMS's nix derivation does **not** regenerate it from .frag at build time. Forgetting to commit the .qsb leaves users with the old visual.
